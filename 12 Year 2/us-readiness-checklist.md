# US / International Relocation Readiness Checklist

This checklist is a planning tool, not legal or immigration advice and not a guarantee of sponsorship.

Use it to identify evidence and gaps before an active international/US campaign.

## Professional seniority evidence

- [ ] I can explain at least 3 meaningful backend projects/workstreams with my own technical decisions.
- [ ] I can describe measurable impact without exposing confidential employer information.
- [ ] I can explain trade-offs involving data, APIs, reliability, performance, or architecture.
- [ ] I have evidence of ownership beyond assigned CRUD tickets.
- [ ] I can discuss production incidents/debugging and validation of fixes.
- [ ] I can explain code/design review contributions.

## Backend depth

- [ ] PHP/runtime fundamentals are independently demonstrated.
- [ ] Laravel/backend framework knowledge goes beyond CRUD conventions.
- [ ] I can reason about MySQL modeling, indexes, query plans, transactions, and concurrency.
- [ ] I can explain Redis data structures, caching, invalidation, and failure modes.
- [ ] I can design HTTP APIs with security/idempotency considerations.
- [ ] I can reason about queues, retries, DLQs, idempotent consumers, and distributed failure.
- [ ] I can discuss observability and production diagnosis.

## Cloud and delivery

- [ ] I can explain an AWS architecture I have built, operated, or deeply implemented.
- [ ] I understand IAM/networking/compute/data-service trade-offs.
- [ ] I can explain container/runtime behavior.
- [ ] I can discuss CI/CD and safe deployment/rollback.
- [ ] I can reason about Terraform state/workflows.
- [ ] I have monitoring/metrics/tracing evidence.

## System design

- [ ] I can lead a 45–60 minute backend/system-design discussion in English.
- [ ] I can estimate basic capacity/throughput.
- [ ] I can identify bottlenecks/failure modes.
- [ ] I can discuss consistency, caching, partitioning, queues, retries, and database choices.
- [ ] I can explain trade-offs rather than listing technologies.

## Coding interviews

- [ ] I can solve common arrays/strings/hash-map problems under time pressure.
- [ ] I can use stacks/queues/binary search appropriately.
- [ ] I can traverse trees/graphs with DFS/BFS.
- [ ] I understand two-pointer/sliding-window/heap patterns.
- [ ] I have practiced recursion/backtracking/basic dynamic programming.
- [ ] I can explain complexity and test edge cases in English.

## Professional English

- [ ] I can explain architecture without translating sentence-by-sentence.
- [ ] I can participate in technical disagreement clearly.
- [ ] I can write useful PR/design comments in English.
- [ ] I can tell behavioral stories with clear context/action/impact.
- [ ] I can ask clarifying questions naturally during interviews.
- [ ] I can recover from not understanding a question without freezing.

## AI-assisted engineering

- [ ] I can use coding agents productively without surrendering review responsibility.
- [ ] I can show examples where I rejected or corrected agent output.
- [ ] My SOLO evidence remains strong on core backend topics.
- [ ] I understand tool permissions, validation, evals, and AI security boundaries.
- [ ] I can discuss one AI-enabled backend capability beyond prompt writing.

## Career evidence

- [ ] Résumé is impact/evidence oriented.
- [ ] GitHub/public portfolio is current and employer-safe.
- [ ] I have practiced technical and behavioral interviews recently.
- [ ] I know the target role family rather than applying indiscriminately.
- [ ] I have recent market evidence about recurring role requirements.

## International exposure

Useful but not mandatory evidence:

- [ ] international customers/stakeholders;
- [ ] distributed team;
- [ ] English meetings/design reviews;
- [ ] cross-border project ownership;
- [ ] internal global network or transfer possibility.

## Sponsorship / relocation research

Before making claims or decisions:

- [ ] verify current company-specific sponsorship/transfer information;
- [ ] verify current immigration pathways with authoritative sources or professional advice;
- [ ] separate remote-from-Brazil opportunities from actual relocation;
- [ ] understand compensation/location trade-offs;
- [ ] understand family/timing constraints privately.

Do not rely on old blog posts or assume a company sponsors because it did in the past.

## Readiness decision

Do not convert this checklist into a single numeric readiness score.

Classify dimensions as:

```text
demonstrated
needs-refresh
gap
unknown
```

An active campaign is reasonable when core professional/backend/English/interview dimensions are broadly demonstrated and remaining gaps are narrow enough to remediate alongside applications.

Real market feedback then refines the private plan.
