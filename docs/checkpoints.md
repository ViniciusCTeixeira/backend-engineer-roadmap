# V1 Approval Checkpoints

These human-review gates control progression through the implementation plan. Work may be prepared before a gate, but later dependent work must not proceed until the named checkpoint is accepted.

## C1 — 52-week matrix and Week 0 diagnostic blueprint

Approve the exact 52-week curriculum matrix together with the Week 0 diagnostic blueprint. Confirm sequencing, transversal tracks, study modes, phase gates, and progressive job-search timing.

## C2 — Schemas and assessment/scoring model

Approve the public/private data schemas, note frontmatter, assessment record structure, scoring dimensions, weights, mastery thresholds, adaptation rules, review behavior, and workload ceiling behavior.

## C3 — Agent rules and command recipes

Approve shared Codex/Claude governance, public/private write boundaries, history and assessment integrity rules, source-quality requirements, and the command recipe catalog.

## C4 — Project progression and resource policy

Approve the progressive project portfolio, project sequencing against the curriculum, engineering-artifact expectations, AI-mode declarations, and the resource curation/freshness policy.

## C5 — Generated sample month validated

Validate one representative month for clarity, workload, source quality, difficulty, AI dependence, assessment/review behavior, project alignment, and Obsidian usability using synthetic learner states.

## C6 — Full 52-week generation allowed

Explicitly authorize full public curriculum generation after the preceding design artifacts and representative sample have passed review. Without C6 approval, generate no complete 52-week daily content.

## C7 — Public-release QA passed

Confirm clean-clone onboarding, private-state initialization and ignore behavior, agent write boundaries, assessment integrity, resource freshness, static validation, and the approved V1 success criteria before release/tagging.
