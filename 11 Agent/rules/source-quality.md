# Source Quality and Freshness

## Priority

Prefer:
1. official documentation / primary specifications;
2. official vendor/university training;
3. respected open-source educational material;
4. high-quality community material;
5. paid material only when materially better and a free path remains complete.

## Required metadata

Public resources should record:
- title;
- URL;
- topic IDs;
- type;
- source authority;
- language;
- cost;
- last verified date;
- version scope when relevant;
- technology depth where relevant.

## Freshness

Always verify current official sources before public edits involving fast-moving subjects, including:
- Codex;
- Claude Code;
- OpenAI/Anthropic APIs;
- MCP;
- AWS certifications/service behavior when version-sensitive;
- PHP/Laravel supported/current versions;
- rapidly changing AI/cloud tooling.

## Durable concepts vs vendor facts

Teach durable concepts in the curriculum. Keep transient model names, prices, limits, and UI steps in dated/versioned resource notes.

Never invent a resource or claim verification that did not occur.
