# Year 1 Target Role

## Primary role family

The roadmap targets:

```text
Senior Backend Engineer
Senior Software Engineer — Backend
Senior PHP Backend Engineer
```

The intended professional identity is broader than a framework:

```text
PHP/Laravel | MySQL | Redis | AWS | Distributed Systems | AI-Assisted Development
```

CakePHP experience is useful evidence of production experience, framework depth, and legacy modernization. It should not become the only role filter.

## What a stronger role means

A target role is stronger when it offers meaningful evidence across several dimensions.

### Backend depth

- non-trivial domain/business logic;
- APIs and integrations;
- database design/performance;
- caching;
- queues/background jobs;
- concurrency/idempotency;
- distributed-system trade-offs.

### Engineering practices

- automated testing;
- static analysis/quality checks;
- code review;
- CI/CD;
- incident/debugging practices;
- technical documentation.

### Production and cloud

- cloud infrastructure;
- containers;
- observability;
- operational ownership;
- security practices;
- reliability/performance work.

### Senior-level scope

- system/design decisions;
- trade-off ownership;
- mentoring/review;
- decomposition of ambiguous work;
- cross-team communication;
- production accountability.

### International-readiness signals

- regular English usage;
- distributed/international teams;
- international customers/stakeholders;
- architecture/design communication in English;
- internal mobility or global office structure.

## Employer-quality rubric

Do not reduce employer quality to one score or salary.

| Dimension | Evidence to look for |
|---|---|
| Backend depth | APIs, data, queues, scale, integrations, ownership |
| Testing | unit/integration/e2e practices stated or demonstrated |
| Code review | PR/review workflow, engineering collaboration |
| CI/CD | automated quality/deployment process |
| Cloud | real production infrastructure, not keyword-only |
| Observability | logs, metrics, tracing, incident response |
| Engineering maturity | design docs, retrospectives, platform practices |
| Learning opportunity | senior peers, meaningful architecture exposure |
| English/international | actual collaboration scope |
| Mobility potential | factual transfer/global structure signals when available |

Use these as independent dimensions, not a universal employer score.

## Signals to investigate

Examples:

- "senior" title with only CRUD/task execution;
- no tests/code review/CI signals;
- framework-only description with no engineering depth;
- production responsibility without observability/support;
- many unrelated technologies with unclear ownership;
- "cloud" that appears to mean only manual server administration.

These are questions to investigate, not automatic conclusions.

## Salary and compensation

Compensation matters, but it is evaluated privately alongside engineering growth, stability, workload, benefits, location model, and long-term mobility.

Never fabricate market compensation. Current comparisons require fresh external evidence.

## Location / relocation

For Year 1, international remote exposure can be valuable even without immediate relocation.

Relocation/sponsorship becomes a primary campaign only after a stronger professional level has been consolidated and readiness evidence supports the move. See `12 Year 2/us-readiness-checklist.md`.
