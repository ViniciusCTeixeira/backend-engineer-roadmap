# LLM / AI Engineering — Week 0 Diagnostic

These prompts diagnose entry depth. They are not public teaching examples and contain no answer keys.

| Field | Value |
|---|---|
| Domain | `llm-ai-engineering` |
| Mode | `SOLO` |
| Assessment type | `conceptual` |
| Difficulty | `diagnostic` |
| Estimated minutes | 25 |

### Prompt

Answer concisely from memory:
1. What is a context window and why does it matter to a backend integration?
2. What is the difference between free-form text output and structured output with a schema?
3. What problem does tool/function calling solve, and what validation still belongs to the application?
4. Name two sources of latency/cost in an LLM-backed request.
5. Why is model output untrusted input even when generated by your own application?
6. When might retrieval/embeddings be useful, and when are they unnecessary?

## `diag-ai-design-001`

| Field | Value |
|---|---|
| Domain | `llm-ai-engineering` |
| Mode | `SOLO` |
| Assessment type | `system-design` |
| Difficulty | `diagnostic` |
| Estimated minutes | 20 |

### Prompt

Design a small support-ticket feature that suggests a draft reply using an LLM, but requires a human to approve before sending.

Cover:
- what context enters the model;
- what data must not leak;
- structured output or tool boundaries;
- logging/tracing;
- evaluation of draft quality;
- latency/cost control;
- prompt-injection/untrusted-content risk;
- what the human approval step protects against.

Keep the design small; do not turn it into a multi-agent system without justification.
